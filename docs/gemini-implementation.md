## Adapter

backend/app/integrations/gemini.py uses the existing httpx dependency and the official Gemini generateContent REST API; no model SDK is needed. The current [stable model page](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite) lists gemini-3.1-flash-lite and structured output support. The [REST structured-output guide](https://ai.google.dev/gemini-api/docs/generate-content/structured-output) describes responseMimeType and responseJsonSchema; the [API reference](https://ai.google.dev/api/generate-content) defines the endpoint and response envelope. Model selection is configurable; availability for a particular account remains unverified until an authorized real smoke test.

Only detached sanitized PaymentEvidence plus backend-approved ID enums is sent. No order/payment/capture/reference/debug/request IDs, descriptions, buyer data, raw provider responses, secrets or tools are included in the payload. The API key is sent in a private x-goog-api-key header, never the URL; settings use SecretStr and repr=False. Canonical HTTPS endpoint is fixed; no custom host, redirects, environment proxy, tool access or automatic retries. No body/key logging.

Response JSON schema accepts only fact_codes/action_codes with IDs derived from the current evidence. Runtime validation rejects unknown/duplicate IDs, unsupported actions, extra state/money/prose claims, blocked responses, non-STOP finish reasons, multiple candidates or nontext/tool parts. FRESHNESS_UNKNOWN is required, and uncertain evidence must retain its nonpayment/missing-capture warning. The existing service revalidates output and never changes stored payment truth. Model contribution is relevance selection/ordering; all displayed wording is explicitly backend-authored. This is not free-form AI explanation, and templates/mocks are never called real AI.

Input is capped at 32 KiB; requested output maxOutputTokens=512; streamed decoded response is bounded (16 KiB default). One total async deadline covers connection, headers and body; httpx also has timeouts. Default five seconds; max 20. Cancellation propagates, streams/clients close, route monitors disconnect and cancels work. Outer service deadline adds 0.5 seconds; frontend evidence deadline is 25 seconds. Errors are reduced to unavailable AI with facts intact. No raw exception/provider payload is returned. A timeout does not alter evidence freshness or payment uncertainty.
